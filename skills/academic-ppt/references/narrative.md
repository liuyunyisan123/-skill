# 汇报主线与图文组织

内容为研究听众服务，尤其要让不熟悉具体代码的同组人员理解每一步的意义。专业术语保留准确名称，用一句话解释用途，不把代码参数清单搬到页面上。

## 背景与必要性

先讲研究对象实际影响什么科学认识或工程判断，再讲已有观测或方法为什么不能充分回答这个问题。介绍选定方法时说明其已有价值，然后指出本研究要补足的具体不足。

新增规则的介绍必须接在对应不足之后：已有处理忽略什么，本次增加什么操作，该操作为什么有用。不要仅写“提高精度”“更合理”“意义重大”。没有证据时不宣称行业共识、普遍最优或首创。

## 每页的任务

按本次研究和时长安排页面，下面是可选的页面角色，不是固定目录或页数：

| 角色 | 听众需要理解的内容 | 适合的证据或组织方式 |
| --- | --- | --- |
| 研究意义 | 为什么要研究这个对象 | 实际观测图，加简短的作用解释 |
| 方法选择 | 为什么采用这条路线 | 两种方法的简洁比较或已有图件 |
| 具体不足 | 现有处理遗漏了什么 | 基线图、相遇或处理实例 |
| 关键方法 | 新增步骤怎样起作用 | 放大的局部图、必要曲线或可编辑流程 |
| 对比设计 | 比较是否能回答研究问题 | 简洁原生表格，交代公平比较条件 |
| 结果 | 在什么条件下观察到什么 | 实际结果图、局部对比和少量关键指标 |
| 结论与后续 | 本次证据支持什么，还缺什么 | 简短发现，明确下一步要验证的问题 |

一页承担一个主要问题；标题点明主题，必要的短结论放在图后。不要重复标题和结论来凑字。无关紧要的背景可省去，但不能省略让方法成立的前提。

## 图多字少的做法

用现场或实验图建立对象认识，用局部放大解释处理变化，再用统计图说明总体结果。图上只保留必要标签，讲稿补充细节。图片复用仅在同一证据需要对照或放大时使用，并清楚标明对应关系。

文字少是减少重复和次要信息，不是删掉必要解释。方法页用简短文字说明“处理什么、怎样处理、产生什么作用”；结果页用一条具体发现联系图表。

需要公式时，页面展示对理解方法确有帮助的一条或少量公式，解释主要变量的含义；完整推导和参数表放备注或用户要求的补充页。PPT公式不默认强制MathType，复杂公式的编辑方式按本次要求和可用工具确定。

## 数字与证据

保留帮助判断结论的数字，如关键改善幅度、比较指标和必要样本说明。不要把多组高精度参数铺满页面。展示值适当取舍位数，计算基于真实源数据，单位和参照对象不变。

拟合结果、模型行为和独立预测是不同证据，不能混写。误差棒明确区间类型，数据不足或区间包含零时使用与证据相称的措辞。详细定义可写备注，决定结论边界的限制仍要在页面简短说明。

展示点与参与指标计算的点可以不同，但要明确筛选规则。样本少的观察可作为辅助展示并清楚区分，不能暗示每个显示点都参与了主指标，也不能以无解释的删点增强结论。

备注写实际讲稿、重要参数、方法条件和来源，方便汇报者回答问题。不要在备注中加入制作过程、文件验证过程或面向Codex的操作说明。
